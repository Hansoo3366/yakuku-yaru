# 동행자 태그

## 개요

직관/집관 기록에 다른 **가입 회원**을 태그. 태그된 사람이 수락해야 상대 캘린더·승률에 반영.

## 상태 머신

```mermaid
stateDiagram-v2
  [*] --> pending: 호스트가 태그
  pending --> accepted: 동행자 수락
  pending --> rejected: 동행자 거절
  accepted --> [*]
  rejected --> [*]
```

## DB

`attendance_companions`

| 컬럼 | 설명 |
|------|------|
| attendance_record_id | 호스트 기록 |
| user_id | 태그된 회원 |
| status | pending / accepted / rejected |
| responded_at | 응답 시각 |

## 알림

| 이벤트 | type | 수신자 |
|--------|------|--------|
| 태그됨 | attendance_tagged | 동행자 |
| 수락 | companion_accepted | 호스트 |
| 거절 | companion_rejected | 호스트 |

## 권한 규칙 (2026-11-16)

| 상황 | 규칙 |
|------|------|
| 태그 인원 | 기록 하나에 최대 10명, 중복 제거 |
| 태그 알림 | 같은 기록으로 이미 알림을 받은 사람에게는 다시 보내지 않음 |
| 기록 열람 | 대기 중이면 볼 수 있음(수락 여부를 정해야 하므로). **거절하면 403** |
| 기록 수정 | 수락한 동행자만. 작성자 기록의 응원 팀·승패는 바뀌지 않음 |
| 동행자의 응원 팀 | 동행자가 고른 팀은 본인의 경기별 응원 팀(`attendance_viewer_preferences`)에만 저장. 수정 화면도 이 값을 먼저 보여 줌 |

## 승률·캘린더

- **수락**된 동행 기록 → 동행자의 기록 목록·통계에 포함
- 같은 경기에 호스트 기록과 동행 기록이 둘 다 있으면 **우선순위**로 dedupe (직관 > 집관, owner > companion)

## UI

- 기록 폼: `CompanionPicker` — 닉네임 검색
- 마이페이지: 알림에서 수락/거절
- 캘린더: `동행` 배지
