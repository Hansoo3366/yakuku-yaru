# 2026-11-16 보안 점검·관리자 개편

하루 동안 서버·배포·의존성·앱 권한을 적대적으로 점검하고, 관리자 화면과 통계 구조를 정리했다. 커밋 11개, 모두 운영 배포 완료.

## 한눈에

| 영역 | 전 | 후 |
|------|----|----|
| SSH 22번 | 전 세계에 열림 | IAP 대역에만 열림 |
| 자동 배포 로그인 | 운영 계정 SSH 키 (셸·sudo 가능) | Workload Identity + 배포 명령만 되는 `deploy` 키 |
| 배포 검사 | `nginx -t` 뒤에서 조용히 끝남 (검사 0회) | 응답 + 컨테이너 확인 2회, `DEPLOY_OK` 필수 |
| Dependabot 알림 | 꺼짐 → 켜자 64개 (critical 7) | 1개 (lint 도구 전용) |
| 앱 낮은 위험 항목 | 5개 | 0개 |
| 관리자 화면 | 2126줄 파일 하나 | 탭 9개 + 개요 탭, 표·상세 패널·토스트 |

## 1. 서버 접근 (6e881f1, fdcf3ee)

- 방화벽: `default-allow-ssh`를 IAP 대역(`35.235.240.0/20`)으로 좁히고, 외부에는 80/443만 둠.
- GitHub Actions → GCP 로그인을 Workload Identity로 바꿈. 이 저장소의 `main`에서 돈 workflow만 로그인 가능.
- 배포는 IAP 터널(`localhost:2222`) + 일반 `ssh`(호스트 키 고정)로 바꾸고, 모든 Action을 커밋 SHA로 고정.
- 서버 저장소 remote를 https로 바꾸고(공개 저장소라 서버에 GitHub 키가 필요 없음), 서버에 남아 있던 배포용 개인키 파일을 지움.
- 쓰지 않게 된 Secret 삭제: `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_COMPOSE_PROFILES`.
- 커널 업데이트 대기 중이라 재부팅.

## 2. 앱 보안 (eaca342)

- 깨진 JSON·너무 큰 본문을 400/413으로 바로 답하고 오류 알림을 보내지 않음. (본문 일부가 메시지에 섞여 알림 쿨다운을 비껴가며 알림이 폭주했음)
- 동행 태그 최대 10명, 중복 제거, 이미 알림 받은 사람에게 재알림 안 함.
- 이메일 인증번호 5번 틀리면 사용 불가 (migration 0005).

## 3. 관리자 화면·통계 정리 (74d21a0)

- 관리자: 탭 9개 파일로 분리, 개요 탭 신설, 탭별 건수, 주소에 현재 탭 유지(`?tab=`), 표 + 상세 패널, 브라우저 confirm 대신 화면 안 확인과 토스트, 모바일 카드, 다크 모드.
- 통계: 홈과 마이페이지가 같은 API(`/attendance-records/stats/me`) 결과를 씀. 응원팀 변경·동행 수락 뒤 바로 갱신.
- 홈·캘린더: 계산과 화면을 분리. 오전 9시 전 경기가 전날 칸에 들어가던 날짜 버그(UTC/KST) 수정.

## 4. 의존성 (9d962d7, d2bdbf1, baf4154)

- GitHub 비밀값 검사·push 차단·Dependabot 보안 업데이트를 켬.
- Next 16.3.0 → 16.4.6 (원격 코드 실행 critical 5개), sharp 0.35.5, multer 2.5.0, nodemailer 10.6.0, body-parser 1.20.9, qs 6.16.2, Sentry 11.12.0.
- 이 과정에서 운영 API가 약 30분 중단 → [[lockfile 손편집으로 운영 API 중단]]

## 5. 배포 스크립트 (da93bb0, e5e5c1b, 715ec08)

- IAP 전환 뒤 배포 5번이 모두 `nginx -t` 직후 조용히 끝나고 있었음 → [[배포 스크립트가 중간에 조용히 끝남]]
- 새 API·웹 컨테이너가 새 이미지로 떠 있고 재시작 0회인지 20초 간격 2회 확인. 마지막 `DEPLOY_OK <SHA>`가 없으면 실패.
- 배포 전용 `deploy` 사용자 도입 → [[IAP 터널과 배포 전용 사용자]]
- 예전 배포 키를 운영 계정 `authorized_keys`와 VM 메타데이터에서 지움. `DEPLOY_PATH` Secret 삭제.

## 6. 앱 낮은 위험 항목 (0ff6b26)

| 문제 | 수정 |
|------|------|
| 갱신 응답 유실·탭 동시 갱신 시 로그아웃 | 회전 후 30초 안의 재사용은 같은 계열 새 토큰 발급. 그 뒤 재사용은 계열 전체 차단(기존 보호 유지) |
| 동행자가 고치면 작성자 응원 팀·승패가 바뀜 | 작성자 기록은 그대로, 동행자가 고른 팀은 본인 경기별 응원 팀에만 저장 |
| 거절한 동행자가 기록을 봄 | 거절하면 403. 대기 중은 계속 볼 수 있음 |
| 팔로우·언팔로우 반복 알림 도배 | 같은 사람의 팔로우 알림은 24시간에 한 번 |
| `page=1e300`이면 500 | API 전체 숫자 검사를 `Number.isSafeInteger`로 |

로컬 API + MySQL로 실제 요청 17개를 보내 확인. 그 과정에서 "동행자가 고른 팀이 저장되지 않는" 버그를 하나 더 찾아 함께 고침.

## 하지 않기로 한 것

- minimatch 알림(#66): lint 도구 전용, 운영 이미지에 없음. 고치려면 lint 도구 메이저 업그레이드 필요.
